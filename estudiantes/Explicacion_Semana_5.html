1. Conceptos Clave (Explicados para todos)

Para entender la Semana 5, no necesitamos definiciones de libro, sino analogías que cualquiera pueda visualizar.

¿Qué es una Lista Enlazada?

Imagina una búsqueda del tesoro: Tienes un papel en tu mano que dice dónde está la primera pista. Vas a ese lugar, y allí encuentras el tesoro... pero también otro papel que te dice dónde está la siguiente pista. No sabes dónde están todas las pistas al principio; solo sabes dónde está la primera. Para llegar a la pista 10, obligatoriamente tienes que pasar por las 9 anteriores. Eso es una lista enlazada: una cadena de "estaciones" donde cada una conoce solo a la siguiente.

Lista Simple vs. Lista Doble

La diferencia es el camino de regreso:
En una Lista Simple, el camino es de un solo sentido. Si te pasaste de la pista que buscabas, tienes que volver al inicio y empezar todo el recorrido de nuevo.

En una Lista Doble, cada pista tiene dos papeles: uno que te dice dónde está la siguiente y otro que te dice dónde estaba la anterior. Ahora puedes caminar hacia adelante y hacia atrás sin perderte.

2. Análisis del Código

RepositorioEnlazado.java: El truco del puntero "Último"

Normalmente, agregar algo al final de una lista es lento porque tienes que caminar desde el inicio hasta el final. Para evitar esto, usamos un "atajo".

La analogía del portero: Imagina que la lista es una fila de personas. En lugar de preguntarle al primero "¿quién es el último?" y que él le pregunte al segundo, y así sucesivamente, tenemos a un portero que siempre tiene la mano puesta sobre el hombro de la última persona de la fila. Cuando llega alguien nuevo, el portero simplemente le dice: "ponte detrás de él". El tiempo de espera es cero, sin importar si hay 10 o 10 millones de personas. 
// El "portero" es el atributo 'ultimo'.
if (primero == null) {
    primero = nuevo;
    ultimo = nuevo;
} else {
    ultimo.setSiguiente(nuevo); // El portero conecta al nuevo al final
    ultimo = nuevo;            // El portero ahora sostiene al nuevo
}

HistorialNavegable.java: El Cursor de Control

Aquí aplicamos la lista doble para crear un sistema de navegación similar al de un navegador web o un editor de texto.

El dedo índice: El "cursor" es como tu dedo índice señalando una acción en una lista. Gracias a que la lista es doble, puedes mover tu dedo hacia arriba (acción más reciente) o hacia abajo (acción anterior) sin tener que soltar la lista y empezar la búsqueda desde el principio.

3. Reorganización de Carpetas

Pasamos de un "caos organizado" (todos los archivos en una carpeta) a una estructura de Paquetes por Responsabilidad. Esto es como organizar una cocina: los cuchillos en un cajón, las especias en otro y las ollas en el armario.

¿Por qué hacemos esto?
1. Escalabilidad: Si el proyecto crece a 100 clases, no queremos buscar en una lista infinita.
2. Encapsulamiento: Podemos decidir qué cosas son "privadas" del paquete y cuáles son "públicas" para el resto del sistema.
3. Orden Mental: Al abrir la carpeta repository, ya sabes que allí solo encontrarás lógica de almacenamiento, nada de interfaz ni de análisis. 
src/
 ├── model/       (El "QUÉ": Datos puros)
 ├── repository/  (El "DÓNDE": Almacenamiento)
 ├── sorting/     (El "CÓMO": Ordenar)
 ├── search/      (El "BÚSQUEDA": Localizar)
 ├── analysis/    (El "PARA QUÉ": Estadísticas)
 └── ingest/      (El "ENTRADA": Carga de datos)

4. Cultura de Tests (JUnit)

No confiamos en que el código "parece funcionar". Usamos pruebas automatizadas para garantizar que cada pieza es sólida.

La analogía del control de calidad: Imagina que fabricas tornillos. No esperas a que el puente se caiga para saber si el tornillo era débil. Usas una máquina que aprieta el tornillo hasta que se rompa y anota la fuerza exacta. Un Test Unitario es esa máquina: le damos una entrada específica y verificamos que la salida sea exactamente la que esperamos. Si cambiamos algo en el futuro y el test falla, la máquina nos avisa antes de que el "puente" (la plataforma) se caiga. 
@Test
public void testEliminarMiddleNodeKeepsChain() {
    // Simulamos borrar la pista 2 de la búsqueda del tesoro.
    // Verificamos que la pista 1 ahora apunte directamente a la 3,
    // asegurando que la cadena no se rompa.
}
