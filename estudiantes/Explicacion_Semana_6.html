Prohibir para Resolver: Pilas, Colas y la Magia del Montículo.

1. La Idea Central: Restringir para Ganar

Hasta ahora, nuestras estructuras eran "libres": podíamos meter y sacar datos de cualquier lado. Pero en la vida real, la libertad total es peligrosa. La Semana 6 nos enseña que poner reglas estrictas es lo que hace que un sistema sea confiable.

La analogía de la ley: Imagina que en un hospital cualquiera puede entrar la gente por cualquier puerta y sentarse donde quiera. Sería un caos. Pero si pones una regla: "Solo se entra por la puerta A y se sale por la puerta B", acabas de crear una cola. No has quitado funcionalidad, has creado orden y garantía.

2. La Pila (LIFO) - El "Deshacer"

Una pila es una estructura donde el último en llegar es el primero en salir. En el código, esto es la PilaDeAcciones.

La analogía de los platos: Imagina una pila de platos sucios. Solo puedes poner uno nuevo arriba, y si quieres lavar uno, tienes que quitar el de arriba primero. No puedes sacar el plato del fondo sin tirar toda la torre.

Esto es perfecto para el Ctrl+Z: la última acción que hiciste es la primera que quieres borrar.

Explicación del código fuente:

public String desapilar() {
    if (estaVacia()) return null;
    String accion = acciones[tope - 1]; // 1. Tomamos la acción de la cima
    acciones[tope - 1] = null;          // 2. Borramos la referencia (limpieza de memoria)
    tope--;                             // 3. Bajamos la marca del tope
    return accion;
}

¿Por qué es así? Si solo hiciéramos tope--, el objeto seguiría existiendo en el arreglo aunque la pila diga que no está. Esto se llama "fuga de memoria". Al ponerlo en null, le decimos a Java que ese espacio ya puede ser reutilizado.

3. La Cola Circular (FIFO) - El Buffer de Datos

Una cola es el concepto opuesto: el primero que llega es el primero en salir. Usamos la ColaDeIngesta para recibir datos de los sensores.

La analogía de la fila del banco: Nadie se cuela. El que llegó primero es el primero en ser atendido.

¿Por qué Circular? Imagina que la fila está en un pasillo. Cuando la gente sale por delante, queda espacio vacío. Si la fila sigue avanzando hacia el fondo, eventualmente chocarás con la pared aunque el principio esté vacío. La cola circular es como si el pasillo fuera un anillo: cuando llegas al final, vuelves a empezar por el principio, reciclando el espacio vacío.

Explicación del código fuente:

public boolean encolar(LecturaSensor lectura) {
    if (cantidad == CAPACIDAD) return false; // Validamos por cantidad real, no por posición
    buffer[fin] = lectura;
    fin = (fin + 1) % CAPACIDAD; // El operador % hace que al llegar a 1000, vuelva a 0
    cantidad++;
    return true;
}

La clave: Usar cantidad es vital. En una cola circular, el frente y el fin pueden quedar en la misma posición tanto cuando la cola está vacía como cuando está llena. Solo la variable cantidad nos dice la verdad.

4. El Montículo (Priority Queue) - Urgencias

A veces, el orden de llegada no importa, sino la importancia. Para esto usamos un montículo en la ColaDeAlertas.

La analogía de la Sala de Urgencias: No importa si llegaste hace una hora; si alguien llega ahora con un infarto, esa persona pasa adelante de todos.

El Montículo es un arreglo que "finge" ser un árbol. No usa nodos ni enlaces complicados, solo matemáticas simples para saber quién es el "padre" y quién el "hijo". La regla es simple: El padre siempre es más urgente que sus hijos. Por lo tanto, la alerta más crítica siempre está en la cima (posición 0).

Explicación del código fuente:

private void flotar(int posicion) {
    while (posicion > 0) {
        int padre = (posicion - 1) / 2; // Aritmética para encontrar al padre
        if (esMasUrgente(datos[posicion], datos[padre])) {
            intercambiar(posicion, padre); // Sube la alerta si es más urgente
            posicion = padre;
        } else break;
    }
}

Lógica: Cuando llega una alerta nueva, la ponemos al final del arreglo y la hacemos "flotar" hacia arriba. Si es más urgente que su padre, intercambian lugares. Así, la alerta más crítica siempre "flota" hasta la posición 0.

5. El Dilema del Empate: Inestabilidad

Descubrimos un problema: ¿Qué pasa si dos alertas son igualmente críticas?

El incidente del hospital: Si tenemos tres alertas críticas (una zona escolar, una residencial y una hospitalaria), el montículo podría entregarlas en cualquier orden porque todas tienen la misma severidad.

Esto se llama inestabilidad. Para resolverlo, añadimos un segundo criterio: el orden de llegada. Si la severidad es igual, gana el que llegó primero. Ahora el sistema es justo y predecible.

Explicación del código fuente:

private boolean esMasUrgente(Alerta a, Alerta b) {
    if (a.getSeveridad() != b.getSeveridad()) {
        return a.getSeveridad() > b.getSeveridad();
    }
    // DESEMPATE: Si la severidad es igual, gana el que llego primero (menor ID)
    return a.getOrdenDeLlegada() < b.getOrdenDeLlegada();
}
